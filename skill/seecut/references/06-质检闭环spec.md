# 06 · 质检闭环 spec（v2）

> 上位：`00-总纲` 第 13-15 条。本文件取代 v1 的"agy 自闭环质检组件 spec"（满屏镜像 / 死磕 95 / 像几成百分比 / 维护者熔断，全部作废）。
> 依据：2026-09-23 评委校准实验（绝对打分 vs 两两对比，正样本=参考原片、负样本=判丑的假满屏版）。结论见本文末"为什么这样设计"。

## 一 · 闭环总流程
```
出一版 vN
  ① 硬门 H1：3A 几何自检（scripts/geom-check.mjs，秒级免费）      → 有 FAIL 先改，不进下一步
  ② 硬门 H2：硬伤清单（agy check 模式）                            → 有 FAIL 先改
  ③ 采纳判定：两两对比 vN vs vN-1（agy pair 模式，交换位置跑两次）
        对手 = **当前采纳版**（不一定是上一版）。两次都判 vN 胜 → 采纳 vN；两次都输 → 不采纳，看输的理由：
        若只是新引入的附带问题、核心改动没被批评，可以在 vN 上修掉附带问题出 vN+1，再和当前采纳版比（Round2-4.2 这样做成功了）；否则回到采纳版再改。结论不一致 → 算平手
  ④ 找方向：两两对比 vN vs 同类参考片参考片（agy pair 模式，跑一次即可）
        不看胜负，只读各维度的"差在哪 + 秒数证据" → 作为下一版改动清单
        ⚠ 若参考片是短片段、功能不同，评委可能判我方全胜、读不出方向（Round2-4.2 实测 6 次全胜）→ 改用
          `agy_read.sh 参考片 "逐条列出这段用了哪些剪辑手法（入场、证据呈现、人像调度、手作元素、节奏）"`，拿手法清单对照自己的片子找差距
  ⑤ 停止：硬门全过 且（对比不胜上一版 或 已到 v3 或 只剩小修补）→ 交付（成片 + 剪映草稿）
```
- v1 没有上一版：跑 ①②④，按④的差距清单出 v2，再从 v2 起走完整闭环。
- **每版改动要肉眼可见**（首测教训：v3-v5 只修 agy 挑的小毛病——印章早退 1s、标签挪几十 px——作者看不出区别，却各占一整轮评审）：每一版必须包含至少一项④找出的大差距；①②的硬伤小修补合并进同一版。
- **长素材**：评审用的视频本来就会降到 540p；渲染迭代版用 `RENDER_SCALE=0.5`。素材超过 1 分钟时，两两对比可以挑改动最大的 30-60 秒片段来比，不必每次整片。
- **时间预算**（首测 2.5h 太慢）：v1 约 30 分钟；之后每版"构建渲染 3-7 分钟 + 评审约 2-4 分钟"。check 和 pair 可以同时跑；等评审时去准备下一版的改动清单，别干等。
- 每一步的原始输出存 `<工程>/qc/vN-*.json`，交付报告引用。

## 二 · 硬门 H1：3A 几何自检
见 `07-几何规则自检spec`：撞位 / 压人像 / 圈锚偏移 / 无脸 ≤5s / 逐词 timing 不抢拍 / 弹簧 overshoot / 空拍。能用数据算的一律数据说话；agy 说"没弹簧""压脸"等，以几何数据为准。

## 三 · 硬门 H2：硬伤清单（agy check 模式）
`python3 scripts/agy_judge.py check --video vN.mp4 --html <master.html>`，逐条过/不过 + 秒数证据：
| 条 | 内容 | 不过的样子 |
|---|---|---|
| C1 假证据 | 有没有用抽象占位窗口、伪代码网格、假 Mac/假 App 界面、无关装饰窗口冒充证据或填满画面 | 总纲第 5 条 |
| C2 证据缺口 | 口播提到真实产品/网页/数据时，画面是否给了真证据（没有=列出是哪句） | 不是 FAIL，是待补清单，交给"找证据"环节 |
| C3 版面 | 元素撞位、遮挡关键信息、上一拍残留、无意义漂浮元素、穿帮 | — |
| C4 人像连贯 | 人像形态无故切换（方↔圆）、位置无故乱跳 | 总纲第 10 条 |
| C5 看不懂/读不完 | 文字闪现读不完、信息看不懂 | — |
| C6 敏感字 | 画面出现可读敏感字 | 总纲第 7 条 |
| C7 空拍 | 连续 ≥2 秒画面几乎无信息、只有一行字 | 总纲第 6 条 |
- C2 只产出清单不判 FAIL；其余任一 FAIL 即不过门。
- **agy 报的 FAIL 必须核实**：脚本会把 FAIL 证据里的时间点自动抽帧到 `<out>_failframes/`，执行窗读这些帧 + 对照 H1 几何数据判真假。agy 有稳定的"串场"毛病（把相邻两拍当成同屏，2-4 v2 上两次误报 14-15s"残留撞位"，抽帧核实两拍是整屏切换、从未同屏）。核实为假的写进报告"agy 误报"，不改片。

## 四 · 两两对比（agy pair 模式）
`python3 scripts/agy_judge.py pair --a vN.mp4 --b vN-1.mp4 [--html-a ... --html-b ...]`
- 脚本自动交换位置跑两次，输出 `consensus`：`A` / `B` / `tie`。
- 维度：证据真实性、名词响应、人像露藏与卡化、动效物理、手作质感、视觉系统一致、版面干净、节奏与画面变化、整体观感。
- 找方向时 `--b` 换成 `金锚集/` 里同功能、同"有据/无据"的参考片（选法见 `金锚集/README.md`）；此时只读 dimensions 的证据，不看 winner。

## 五 · agy 调用纪律（脚本已内置，手动调用也必须守）
1. 每次 `--new-project`（agy 有按项目的持久记忆，旧项目会被别的片子污染，喂啥都串成那条片）。
2. `--output-format json --json-schema <schema>`；解析取最后一个含目标字段的 JSON 对象（agy 回复里会夹思考文本/噪声）。
3. **指纹核**：prompt 要求照抄画面文字；脚本检查这些文字是否出现在本片 `master.html` 源码文字 **或 同目录 `fp-manifest.txt`**（≥2 条命中才有效）。`fp-manifest.txt` = 执行窗读证据图核敏感字时，顺手把图里看得清的字逐行记下（agy 常照抄截图里的字，源码里没有）；也可 `--fp-extra` 另给清单。时长核：agy 报的时长与 ffprobe 实测差 ≤3 秒。不过=判 confab，重跑 1 次，再不过=标"agy 无效"，不当有结果继续。
4. 视频压到短边 540p 再喂；prompt 里写"禁止启动后台 OCR/转录/采样子任务"。
5. **评委隔离**：脚本把视频复制到系统 tmp 的独立目录再调 agy，并声明"不要读取其它文件"——2-4.1 实证：临时目录建在工程里时，agy 读到了 master.html 和 runlog，评判被源码污染。手动调用 agy 也必须这样隔离（素材理解用 `scripts/agy_read.sh`）。
6. **退出码**：0=通过/有共识；1=check 有 FAIL；2=无效（agy 两次都没给出可信结果——**不是通过也不是不通过**，报告里写"无结果"）；3=agy 授权过期，停下请用户重新登录。
7. **快速失败**：单次调用超时 240s；接口断连/超时立即重试（不算内容无效），指纹/时长不过才算内容无效、最多重跑 1 次。pair 两序并行。
8. agy 判定有波动：同一版两次 check 的 FAIL 集合可能不同。单次 FAIL 先抽帧核；核实为真的才改。
9. 代理与账号地区见 README 依赖段。

## 六 · 交付报告（给用户）
- 成片路径 + 每版一行：硬门结果、对比结论（vs 上一版）、这一版改了什么。
- 找证据环节：拿到了哪些真证据、哪些没拿到（原因）、敏感字核查结果。
- agy 误报清单（抽帧核实为假的）。
- 已知未解决项 + 需要用户决定的主观项。

## 七 · 为什么这样设计（校准实证，2026-09-23）
- **绝对打分不可用**：11 条款各 0-2 分求和，判丑的假满屏版 v6 = 18 分，与参考原片最高分同分；干净版 v3 与 v6 同分。只有"证据真实性"一条能把原片和我们的片分开。→ 绝对分只保留成硬伤清单，不求和、不当迭代信号。
- **两两对比可用**：原片 vs 我们的片，交换位置两次都判原片胜；同一工程 v1 vs v2，两次都判 v2 胜（与人工复核一致）。
- **两两对比的盲区**：干净 v3 vs 假满屏 v6，两次都判 v6 胜——抽帧核实 v6 前景确实更好（名词接得住、人像撕纸框），但背景是假占位网格，用户肉眼判它更差。→ 假证据必须由硬门 C1 + 生产端总纲第 5 条直接禁掉，不能指望对比评委扣分。
- **"像参考片几成"百分比作废**：同片同 prompt 两次 88-90% vs 68-70%；修真 bug 分数不动；把分数往上推的唯一路径曾是"铺假满屏"，与用户肉眼方向相反。
- **素人视角 prompt 作废为评委**：它给参考原片 62 / 45 分、给我们的干净版 90 分，衡量的是"清爽克制"而非网感口播精剪风格；其有用的部分（看不懂/读不完/空拍）已并入硬伤清单 C5/C7。
