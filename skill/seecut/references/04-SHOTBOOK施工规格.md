# SHOTBOOK 模板与施工规格（管线步骤②③）

> 作用：把《编排层决策表》+《Design Reference》+两仓卡库 串成"每镜可填、可施工"的表。这是步骤②(编排)+③(判断补素材)的落地件。
> 依赖：`编排层-文本驱动决策表.md`(功能→人像层/信息层) · `参考片-Design-Reference-设计令牌.md`(两层:内核+可变) · `视觉质量地板-审美对齐清单.md`(护栏)。

## 第0步 · 先定全片"可变层"（填镜之前必做）
参考片是"恒定内核+按内容自适应"，所以**开工先给这条片定3个可变项**（Design Reference §0-B）：
1. **强调主色**（色族内选1主色）：如砖红主 / 绿主 / 红黄双主。
2. **像素 or 3D卡通**（风格取向）：题材偏工程/极客→像素CRT；偏情绪/生活→皮克斯3D卡通。
3. **各段落背景策略**：讲操作段→真录屏底；讲概念段→纸质点阵；引用段→满屏真截图；露脸段→真人实景。
> 内核项（动效弹簧+stagger/粗黑体/手作质感/人像卡化/三禁）全片不变，不用选。

## 第0.2步 · 判素材类型（定露藏基调）
按 `02-设计令牌` §6.5 判：①半身口播（真人或数字人完整半身 A-roll）/ ②角落圆 PIP / ③点缀型数字人。**关键看有没有完整口播人像 A-roll**，别把"数字人"一律当③。

## 第0.3步 · ★素材台账（素材理解的中间产出，2026-09-20 新增，必产）
> 作者定：素材理解不能只抽几帧就跳去 SHOTBOOK；要有**可复核的结构化中间产出**，防花样素材翻车。
- **每个素材（粗剪/录屏/截图/B-roll）跑一遍 agy/Gemini 读视频**(成本 作者已批)，别只抽静帧(会漏)。产出一张台账，每行：
  | 素材 | 类型(实拍口播/录屏/截图/图) | 时长/尺寸/帧率 | 画面内容(agy 读) | 可用片段+时间码 | 能当什么信息层 | 本片用/备档 |
- **人像素材特判**：是半身还是角落圆球？→ 定第0.2步基调。
- 台账落 `<工程>/素材台账.md`，是 SHOTBOOK 的原料，也供用户复核"素材理解够不够"。

## 第0.5步 · 填表前先答5个导演问题（融合作者导演编排表精华）
先理解整篇文案逻辑、拆成语义段落（**不按标点/句长/停顿机械切镜**）。每一镜先答：
1. 这一段最需要观众理解什么？
2. 什么画面能让这句话更具体、更好懂？
3. 画面主体要发生什么变化？
4. 镜头最后停留在什么结果上？
5. 它如何承接上一镜、自然进入下一镜？
**🔴 anti-偷懒铁律**：入场动画、呼吸循环、背景循环、字幕出现**都不算"有效信息变化"**；避免画面长时间没有新内容，也别让动画为了动而动。（呼应质量地板）
**时间纪律**：镜头起止落在**短语边界**，不跨语义切开；时间戳以转写时间轴为准、不自行估算不改。

## 第1步 · 逐镜 SHOTBOOK（每句口播一行）
| 镜# | 时间 | 口播原话 | 功能(13类) | 有据/无据 | 证据计划(拿什么真证据/从哪来) | 人像层 | 信息层组件 | 选哪张卡 | 背景底 | 动态变化(镜内第1/2/3变化) | 动效 | 画面衔接 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

**每列怎么填**：
- **功能**：查决策表13类(hook/建信任/举例演示/讲机制/引用文档/列举/给数字/定调/纠偏/情绪痛点/转折/章节命名/收尾)。
- **有据/无据 + 证据计划（v2 必填）**：这句提到真实产品/网页/文档/数据/操作 = 有据 → 写清要拿哪张真截图/哪段录屏、从哪来(用户素材/自己截/录)；纯观点/情绪/自述 = 无据。**有据镜不许空着证据计划**；背景底按 `02` §3 选底规则跟着有据/无据走。
- **人像层/信息层**：查决策表该功能的主导取值(如举例演示→隐去77%+满屏截图)。
- **选哪张卡（★组件调库规范，2026-09-21 作者重定：默认查官方库、能拿就拿、禁从头造）**：
  - **🔴 铁律：原则上"能直接复用 或 微调即用"就直接拿，不要自己从头造**。2-2/2-3/2-3.1 三窗都"看库找灵感再全手搭"→撞位/圈歪/矢量质感，就是违反这条的代价。
  1. **HF 官方库 = 默认首选探查**（比 student-kit 丰富太多，~168 组件，github heygen-com/hyperframes + hyperframes-launches，`hyperframes` CLI `add`）：正好覆盖参考片所需——`code-snippet-*`(几十种终端/IDE **满屏内容底**)、`reddit-post`/`app-showcase`(真实 UI 底)、`hw-*`(hw-title/hw-scribble/hw-write-title… **真手绘手作**，修矢量圈)、`mk-callout-highlight`/`mk-progress-stat`(荧光圈注/进度)、`apple-money-count`(数字滚动)、`notes-reveal`/`carousel-*`/`flowchart`/`data-chart`/`lt-*`(下三分之一)。**先在这里找。**
  2. **student-kit Vox 库(辅)**：`hyperframes-student-kit/style-library/01-vox-explainer/cards`(106 张)，官方库没有的对应件再来这。
  3. **动效层**：HF `motion-doctrine`(Vector Law/弹簧/连续运镜)+`seam-gate` 自检 + `hw-scribble-transition` 等；不确定 skill 在不在环境则以 Design Reference §5 动效令牌为准。
  4. talkcraft 辅；**不用 Remotion**(慢/占算力；HF 够用)。
  5. **硬规则（总纲第11条）**：本列必须填 registry 组件名，或"库里没有：原因"。用 `npx -y hyperframes@latest catalog`（需大写 `HTTPS_PROXY`）查。参考片直接可用件：`hw-arrow` `hw-callout-circle` `hw-underline` `marker-highlight` `marker-checklist-card` `spring-pop` `stagger-cascade` `badge-pop` `count-up` `number-pop-in` `comparison-split` `before-after-wipe` `browser-device-stage` `device-frame-stage` `code-snippet-*` `terminal-simulator` `x-post` `reddit-post` `yt-comment-card` `chat-message` `notes-reveal` `vox-annotate` `inline-highlight` `card-resize`。
  6. **接线**：registry 组件多是带自预览的独立 composition，要抽 helper 才能塞进单文件 master。手绘三件已抽好在 `assets/hf-hw/`（含墨色覆盖、callout label 慢 1.4s 等坑，见其 README）；新抽的组件也补进 `assets/`，下次直接用。
  - **为什么**：库件的间距/层级/stagger/clip-path/手作质感是设计过的、经战验的——直接拿能少犯撞位/圈歪/矢量感，**别把版式和质感都压给自己手搭 + agy 事后挑**。
  - **何时才手搭**：三个库都没有的（参考片特有像素 CRT / 特定产品 UI mockup）才从零手搭，且**必须过几何自检**；手搭前先记录"为什么库里没有、为什么必须手搭"（2-3.1 就是没记录、直接手搭）。
- **★版式(横/竖)按源素材+交付定，不写死**(作者 2026-09-20)：
  - **源素材/交付是横版** → Vox 横卡(1920×1080)**可近即插**、最省(只蒙令牌)；成片横版。
  - **源素材/交付是竖版 reel** → 复用库卡零件(CSS/clip-path/GSAP/tokens)**按竖版重排**(Design Reference §8.6，铁律①内)，"抄零件+重排"非只微调。
  - 开工第 0 步先定这条片的画幅(看素材/交付)，再决定"即插 or 重排"。
- **蒙皮**：这镜用第0步定的背景底+主色；卡按 Design Reference 内核令牌改CONFIG(色/字/圆角/阴影/缓动)，不改运动命门。
- **素材来源**：见第2步。
- **动态变化(镜内)**：按旁白顺序写这一镜内第1/2/3次变化(主体出现/重点放大/两方案对比/步骤展开/信息从乱到清/结论落定)；长镜头必须有内部变化，没必要别凑数。**入场/呼吸/字幕不算变化**(见0.5)。
- **动效**：内核=弹簧回弹(back.out/overshoot)+stagger入场，禁匀速线性；转场=运动承接(缩窗pinch)/章节卡换幕，禁硬切。
- **画面衔接**：写清与前后镜如何通过主体/动作/方向/位置/颜色/意义自然接续，**不许只写"淡入淡出"**(呼应motion-doctrine的Vector Law:出场决定入场、同轴同向匹配)。

## 第2步 · 素材需求判断（步骤③，以参考片密度为基准）
每镜信息层的素材，归入5类之一，缺的进"未采集清单"问用户/生成：
| 素材类型 | 判断 | 从哪来 |
|---|---|---|
| 用户已有 | 用户提供的截图/录屏/图 | 直接用(必要时裁满/去黑边/装饰框) |
| 需现截图 | 讲到真实页面/产品/文档但用户没给 | `node scripts/grab_evidence.mjs <素材目录> <url>...` 截真图(禁mock假UI)；**逐张读图核敏感字**后登记进素材台账 |
| 需生成图 | 概念图/场景图/海报 | AI生图(Grok/生图skill) |
| 需生成像素/3D卡通 | hook像素CRT / 情绪痛点3D卡通(组件缺口) | AI生成 或 降级线稿(schematic) |
| 纯卡库动效 | chip/大字/数字卡/概念卡/进度清单/章节卡 | 两仓卡库直接搭,无需外部素材 |
> **🟢 Grok 自主生图能力(打包进管线,作者定)**：用户不会每次给全素材。缺"图/像素/3D/场景"类素材时，执行窗**自主调 Grok image_gen 生成补足**(需自装 Grok CLI；没有就跳过，降级线稿或问用户要)。**约束只到技术层：透明底/无残边/抠图干净；不锁颜色和设计**(留创作空间)。生不出满意的再降级线稿(schematic)或问用户要。未来可扩到用Grok/视频模型**生视频片段**。
> **以参考片为基准的密度底线**(质量地板)：每个信息拍≥2分层元素、无大黑边、无空拍、有手作质感——达不到就是round2那种"一个小卡飘空背景"。

## 第3步 · 证据缺口清单（步骤③产物）
把"有据镜"里拿不到真证据的逐条列出(镜#/口播原话/想要的证据/没拿到的原因)。能问用户就问；用户不在就按 `02` §3 第4条退回无据打法先做，并在交付报告里列出这张清单。

## 对照示例：round2 "引用Reddit神帖"这一镜，错 vs 对
| | round2(错) | 参考片式(对) |
|---|---|---|
| 背景 | Reddit横截图留巨大上下黑边 | 截图**裁满/竖构图重排**，或纸质点阵底上放截图卡 |
| 人像 | 光秃秃小圆头 | 撕纸毛边/圆角PIP，带白描边+柔和阴影 |
| 信息层 | 就一张静态截图 | 截图 + **荧光圈注"147"**(Vox section-highlight) + 手绘箭头 + 字幕条(千层饼) |
| 动效 | 硬切静止 | 截图弹簧入场 + 圈注stagger刷过 + marker音效 |
| 卡 | 无(裸贴) | Vox `section-highlight`/`stat-magnifier` 蒙参考片token |
> round2 的病=每列都取了"最省"的默认值；参考片式=每列都达质量地板。**决策表给"放什么"，Design Reference给"做成什么样"，质量地板兜"不许偷懒到什么程度"。**

## 第4步 · 全片检查（SHOTBOOK填完、动工前过一遍）
1. 画面是否真正帮助理解文案（不是为丰富而切）。
2. 有没有连续重复、节奏单一。
3. 有没有镜头变化太少 或 信息过载。
4. 有没有用未提供/无法核实的素材（不编造）。
5. 重要信息是否得到足够视觉强调。
6. 前后镜是否连贯（Vector Law：出场决定入场）。
7. 哪些镜头需要补素材 或 需你/用户做选择。
**最后单独列三张表**：①需补充的素材（未采集清单）②需确认的视觉方向 ③制作难度较高的镜头。
