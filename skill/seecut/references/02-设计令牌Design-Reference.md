# 《参考片 Design Reference》· 设计令牌（★施工包缺的那块）

> 定位：这是下游"蒙皮"的**单一真相源**——talkcraft/student-kit 的卡都是中性件，进片**必须蒙上这套令牌**才是参考片质感（round2 丑的根=用了默认皮）。对标 talkcraft `design-language.md` / student-kit `tokens.css`。
> 来源：agy 实测两条参考原片(13/02)提取设计DNA + 我抽帧核实(色板/像素/点阵/药丸/涂鸦均已核) + Vox Explainer 令牌结构参照。2026-09-19。
> 风格名：**极客手账风（Geek Craft + Notion Aesthetic）**——极客工位背书 + 手账纸感 + 复古像素 + 弹簧微动效 + 手绘涂鸦。绝不纯黑纯白硬碰撞。

## 0 · 两层结构总纲（★最重要，8条实证修正）
> 更正：初版拿2条样本把"米白纸底/像素"当成了universal，8条复查后翻车。参考片**没有一张固定皮**，是"**恒定内核 + 按内容自适应**"。下游要学的是这套自适应，不是一张死皮。

**A. 恒定内核（跨8条不变，蒙皮的地基）**：
- **动效**：弹簧回弹(cubic-bezier(0.34,1.56,0.64,1)) + 音频驱动stagger(80~120ms) —— 6/6样本全符合，这是"丝滑"的真命门。
- **字体**：无衬线**粗黑体**(800~900)，非衬线(区别于Vox的Fraunces)。
- **强调色族**：青柠/薄荷绿 + 复古砖红 + 琥珀黄（族固定，具体主色可变，见下）。
- **手作质感**：手绘涂鸦箭头 + 荧光笔划线（多数样本有；纯3D卡通条如s10可无像素但仍有涂鸦）。
- **人像卡化**：真人=圆角卡/撕纸PIP/圆形PIP，带边框+柔和阴影（§6），绝不怼脸大头。
- **视觉模块跟功能走**：什么内容配什么模块 = 我们的《编排层决策表》。
- **三禁**：不纯黑#000/纯白#FFF硬碰撞 · 不刺眼纯红大字报 · 不硬切无缓动。

**B. 按内容可变层（每条/每段落自适应，不是硬规则）**：
| 可变项 | 取值随什么变 | 实证 |
|---|---|---|
| **背景底** | 看这段讲什么 | 讲录屏操作→真录屏底(暗IDE/白UI) · 讲概念→米白纸质点阵/纯色画板 · 引用→满屏真截图。**样本13一条就4种底** |
| **强调主色** | 每条选一个主色调 | 13砖红主 / 03·10绿主 / 11红黄双主(都在色族内) |
| **像素 or 3D卡通** | 风格取向(创作者/题材) | 13·04·11像素CRT / 10·02皮克斯风3D卡通 |
> 🔴 唯一的背景硬规则：**永远不把主讲人虚化铺底当背景**（round2的病）。背景可以是真录屏/纸质/纯色，就是不能是模糊人脸。

## 3 · 背景/幕底（按这段讲什么选；v2 与 `00-总纲` 第4-7条一致）
> v2 修订说明（详见 CHANGELOG）：v1 的"默认干净、真素材执行窗不主动够"已撤销。当时判丑的"满屏"其实是**假证据满屏**（抽象代码窗/占位网格拼贴），错的是"假"，不是"满"。参考片的满屏靠的是**真实、相关、连贯**的证据。

### 选底规则（逐段判，按决策表的"有据/无据"）
1. **有真证据的段（讲产品/网页/文档/数据/操作/引用）→ 真证据底**：真截图/录屏满屏铺，配证据镜（滚动/放大/圈注/下划线）；前景卡弹出时底图 20~40px 模糊 + 降对比 + 浅蒙层让位（方法论法则5）。这是参考片的正常做法，**执行窗必须主动去拿证据**（`04` 第2步 + `scripts/grab_evidence.mjs`）。
2. **纯观点/情绪/自述段 → 半身露脸 或 干净设计底**：半身实景（真人/数字人书房）+ 少量关键词卡；或米白点阵纸底(`--paper #F8F5EE`+方阵点+2~3%微噪点) + 前景元素扛密度。
3. **章节/转场段 → 章节卡整屏换幕**（像素/线稿/点阵纸底）。
4. **拿不到证据的"有据段" → 退回第2条**，并在交付报告"证据缺口"里写明缺了什么、为什么没拿到。

### 禁止（总纲第5条）
- ❌ 抽象占位窗口 / 伪代码横线网格 / 假 Mac 三色点窗口 / 假 App 界面，冒充证据或"填满"画面（2-3.1 v6/v7.3 的死因）。
- ❌ 与本段话题无关的装饰截图拼贴。
- ❌ 主讲人虚化铺底当背景。

### 两条底线
- **审核安全**（总纲第7条）：证据截图入片前逐张读图，不得出现可读敏感字（下载/反爬/扫码/搬运/联系方式/加微信/站外引流/违规承诺…）；有就裁掉/打码/换一张，拿不准就不用。
- **不与前景混淆**：底不得被误读成前景卡或字幕。

## 4 · 手作质感元素（5种，破冷感的命门）
1. **8-bit像素**：低分辨率CRT屏(红蓝绿色块) + 像素橙红小怪兽/机器人。用于前3秒概念定调。
2. **白粉笔/蜡笔涂鸦箭头**：边缘粗糙带手抖感的白细线+单线箭头(如指人物头`ADHD ➜`)。直接画在实拍/3D人物上。
3. **荧光笔划线**：半透平头马克笔刷过文本(淡黄/亮绿,两头微透中间实)。说到核心结论时动态刷过。
4. **粗3D立体箭头**：红绿两色圆润厚实箭头,柔和漫反射,斜插/垂直。逻辑分流(静态vs动态)。
> 实现：手绘圈/下划线/箭头用 `assets/hf-hw/`（HF 官方组件），**墨色必须覆盖为 `--red`/`--ink` 等本令牌色**（组件默认 #f4f2ec 是给深色底的，米白底上看不见）。
5. **贴纸+撕纸边**：带小红书/推特微缩图标的贴纸卡；人像/截图边缘不规则纤维毛边(便签随手贴感)。

## 5 · 动效 tokens（"高级丝滑"的本质=弹簧物理+音频驱动stagger）
```
--ease-spring   cubic-bezier(0.34, 1.56, 0.64, 1)   出入场一律弹簧回弹,105~108%overshoot再回100%
--dur-in        0.25~0.35s
--stagger       80~120ms(约3~4帧)  元素绝不同步出,按口播语调级联下落
                典型序列:黑药丸标题弹出→3D箭头刺入(Y-30→0弹性)→白卡展开→荧光/代码标签随重音最后现
--camera-breath 真人全屏时极缓推镜 ~1%/秒(增强专注)
--punch-in      重要转折无缝跳切放大1.15~1.2x(中景→近景,无转场,制造力量感)
--window-pinch  全屏真人→演示:整窗收缩(pinch),平滑变形+赋圆角阴影,退成角落PIP(逻辑连贯不断层)
```
🔴 round2 的病=硬切+无缓动默认件。正确:每个卡/字/箭头都挂 --ease-spring + stagger。

## 6 · 人像卡规范（真人=组件化,不是怼脸大头）
```
① 分屏竖向圆角卡(讲解态)：靠右占宽35~40%/高75~80%,左侧留白放大卡文本清单
   圆角20~24px · 1px极细半透边rgba(0,0,0,0.06) · 多层柔和阴影 box-shadow:0 16px 36px rgba(0,0,0,0.08)
② 左下圆形PIP(全屏演示态)：直径占宽20~25%,左下留边~30px,正圆裁切+3~4px纯白描边(现场引路人)
③ 撕纸毛边开场卡(概念切入态)：手撕纸质白边+微翘曲阴影,居中或下方
④ 真人实景背书：暖光台灯+双屏暗色IDE+原木书架+高达/机械臂模型+玻璃台面倒影(极客专业感)
```
🔴 round2 的病=怼脸大头顶中上部 + 光秃秃小圆。正确:上面三种卡形态之一,带边框/阴影/留白。

## 6.5 · 素材类型 × 露藏基调（开工第一步判定）
> 先按素材类型定基调，再按句子功能（决策表）微调。关键区分：**有没有完整的口播人像 A-roll**。

| 素材类型 | 人像形态 | 露藏基调 | 关键规则 |
|---|---|---|---|
| **①半身口播（真人实拍 或 数字人完整半身 A-roll，如 2-2、2-4 数字人）** | 可半身大露 / 缩卡化小窗 / 藏 | 按"对你说露、给你看藏" | 演示/信息拍缩或藏让信息层唱主角；观点/情绪/收尾放大半身；竖版可用"上信息卡 + 下半身"分屏 |
| **②角落圆 PIP 素材（如 2-3）** | 角落小圆，露成本低 | 默认多露少藏 + 有调度 | 自述/感叹/总结必露且情绪拍放大；纯演示拍缩小退让；别全程常驻不动 |
| **③点缀型数字人（没有完整 A-roll，只有几个镜头）** | 只点缀 | 音频为骨架，数字人少露 | 只在 hook/情绪/总结出现；其余按"有素材→信息层 / 无素材→图形组件或大字卡"填 |

- **通用**：自述、感叹、总结/观点句 = 该露；纯给你看的信息/演示 = 可藏让位；无脸连续 ≤5s；人像形态全片统一、位置变化跟着功能走（总纲第10条）。

## 7 · 音效体系
- **BGM**：Tech-LoFi/Chillhop 95~110BPM,电钢琴琶音+电子鼓;**sidechain侧链闪避**,人声开口BGM下潜-18~-24dB。
- **微音效**：①bubble-pop木鱼声(卡片/像素/黄块/气球弹出,80~150ms) ②机械键click(命令/终端) ③marker-swipe沙沙(涂鸦/荧光划线) ④whoosh薄纸风(卡片滑入/PIP缩放/跳切) ⑤ping清脆铃(步骤完成/文件生成)。

## 8.5 · 引擎按段渲染再拼（两仓混用施工说明，补B）
- **引擎不互斥**：talkcraft卡=Remotion(.tsx)，student-kit/Vox卡=HyperFrames(.html)。二选一**只发生在"单个合成文件内"**，最终成片可混。
- **施工方式=按段/按元素各自原生渲染 → 合成器拼**：
  1. 每个信息层卡：用它所属引擎渲成片段（Vox卡→HyperFrames渲；talkcraft卡→Remotion渲），可带透明通道(webm/PNG序列)。
  2. 人像层：真人clip按§6卡形态(圆角/撕纸/圆形PIP)裁框。
  3. **在合成器(剪映时间线 / ffmpeg overlay)上分层叠**：底(音轨+背景底) + 信息层卡(各引擎渲出的片段) + 人像层PIP + 字幕(剪映)。
- **对齐**：卡的入场时刻锚口播节拍(用SRT词级时间)；音效点对齐弹入帧。
- **提速**：host降720p、测试段先渲；Remotion渲染本身不慢(段级几分钟)，别被4K编码/僵尸进程拖(round2教训)。
- 结论：不选A/B引擎，**哪张卡贴参考片就用哪个引擎渲那一段，最后拼**。Vox贴参考片→多数信息卡走HyperFrames；talkcraft补talkcraft独有的。

## 8.6 · 版式按源素材/交付定；竖版时按零件重排（2026-09-19起，2026-09-20补）
> ★前提(作者 2026-09-20)：**画幅横/竖按源素材+交付定，不写死竖版**。源/交付是横版→Vox 横卡(1920×1080)可近即插、最省；源/交付是竖版 reel→才需下面的按零件重排。开工第0步先定画幅。
### （以下为竖版 reel 情形）
- **问题**：Vox卡原生是 1920×1080 **横版**，reel是 2160×3840 **竖版**，卡verbatim塞竖frame=上下大片空纸(犯质量地板"卡飘空背景")。
- **正解=按零件重排(不是verbatim复制横卡)**：**复用Vox的真零件**(clip-path撕纸/报纸纹理/GSAP弹入/tokens/CSS类)，**只重排布局**成竖版满frame。
- **铁律①判定(方法论owner定)**：这**在红线内**。铁律①本意=禁"脱离真设计系统、凭空手捏样式冒充"，**不是禁改布局**。用真设计系统零件按目标画幅重排=正当；漂移成手绘lookalike冒充才越线。
- 实证：Round2-2 的 S1 竖版重排(撕纸标题+药丸高亮+点阵纸底+手绘下划线+像素robot+手写旁注)满frame、三禁全过、真参考片质感；横卡当带那版上下大空纸=淘汰。proof: 作者本地过程记录（未收录）。

## 9 · 一句话落地速查
底色改 `#F8F5EE` + 6%噪点 + 30px点阵；标题 ExtraBold 无衬线字距-1~2%，关键词用砖红/青柠绿或深药丸反白；入场一律弹簧缩放0.25~0.35s + stagger 3~4帧；每个动效点对齐一记 bubble-pop/marker/key/whoosh 音效；真人只走三种卡形态；**永远不模糊人脸当背景、永远不用刺眼纯红大字报、永远不硬切**。
